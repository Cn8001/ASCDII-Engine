Install

ASCDII Engine consists of three programs, each with its own icon.

ProgramFunction
ascdiiThe command line tools; ascdii run opens the editor. Without arguments it prints the list of commands. See CLI reference.
ascdii-editorThe desktop editor. It is opened through ascdii.
ascdii-playerRuns games in the terminal. Every build starts from a copy of it, see Build.

Installation

PlatformArchiveContents
Windowsascdii-0.0.1-windows-amd64.zipascdii.exe, ascdii-editor.exe and ascdii-player.exe
Linuxascdii-0.0.1-linux-amd64.tar.gzascdii, ascdii-editor and ascdii-player
  1. Extract the archive for the platform into any folder, for example C:\Tools\ascdii or ~/tools/ascdii. The files must remain in the same folder.
  2. Optionally, add that folder to PATH to run ascdii from any location.

Starting the engine

  1. Run ascdii run in a terminal. The editor opens at its start screen. ascdii run <project> opens it with a project, given as its folder or its .ascdiiproj file.
  2. To start the editor with a double click on Windows, create a shortcut to ascdii.exe and append run to its target. The console window of the shortcut closes as soon as the editor starts.
  3. To create a project, select a template, enter a name, choose the location with Location and press Create. To continue, select a recent project, or press Open to choose a .ascdiiproj file.

The start screen returns when a project is closed. Starting ascdii-editor directly also works: it restarts itself through ascdii run. A double click on ascdii.exe itself shows the list of commands and waits for Enter.

Terminal requirements

Games require a terminal with 24 bit color and a font that includes the Braille block (U+2800 to U+28FF). Supported terminals include Windows Terminal, WezTerm, Kitty, Alacritty, GNOME Terminal, iTerm2 and the Visual Studio Code terminal. A window of at least 120 by 40 cells is recommended.

ascdii version
ascdii play ~/games/demo

The appearance depends on how the terminal's font draws Braille characters. Many fonts draw them as small dots with wide gaps, which makes the image look sparse and dark; a smaller font size gives more columns and more detail. Terminals whose fonts draw Braille poorly can run games in block mode, which uses half block characters instead and does not depend on the font:

ascdii play ~/games/demo --blocks
Quest\Quest.exe --blocks
WindowsUse Windows Terminal; the legacy Windows console host does not support 24 bit color.
Distributing gamesBuilt games run on their own and require only a terminal. See Build.

Building from source

Required only for development of the engine and the editor. All programs build from one Go module.

ToolVersionPurpose
Go1.25 or newerEngine, CLI, editor backend
Node.js20 or newerEditor interface (Vue, Vite, Tailwind)
Wails CLIv2.17go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.0
WebKitGTK 4.1 headersLinux and WSL onlysudo apt install libwebkit2gtk-4.1-dev
make test             # vet and tests for the whole module
make all              # bin/linux and bin/windows
make cli              # ascdii and ascdii-player for both platforms
make editor-linux     # ascdii-editor into bin/linux
make editor-windows   # ascdii-editor.exe into bin/windows
make dist             # the archives listed under Installation, in bin/dist

The first make writes .env with a random key for game data, which git ignores; keep it, see The game data key.

bin/linux and bin/windows each hold one complete installation with the same files as the release archive of that platform: ascdii, ascdii-editor and ascdii-player, all for that platform only. A folder runs from any location it is copied to; ascdii starts the editor next to it. Every target first runs make brand, which draws the program icons and the Windows resources that embed them. Windows programs are cross compiled from Linux and WSL without additional toolchains. make editor-dev starts the editor with hot reload and without the launcher, and serves it at http://localhost:34115 for browser developer tools.
