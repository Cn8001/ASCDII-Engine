Lua scripting

Game logic lives in Lua files in your project. Write them in your own code editor; the engine reloads a script the moment you save it. Scripts are components, so an object can have several, and they can find and call each other.

Your first script

  1. Select an object, press Add Component and choose New script. Name it door. The editor creates scripts/door.lua, attaches it and opens it in your code editor.
  2. Replace the file with the code below and save.
  3. Back in the editor the script card shows the fields hero, reach and lift. Drag the hero from the Hierarchy onto hero.
  4. Press play, walk close to the door and press E.
-- scripts/door.lua
fields = {
  hero  = object(),
  reach = range(3, 1, 10),
  lift  = 4,
}

function start(self)
  self.open = false
end

function key(self, k)
  if k == "e" and self.hero and self:distance(self.hero) < self.reach then
    self.open = not self.open
    self:tween("pos.z", self.open and self.lift or 0, 0.6)
    return true
  end
end

function update(self, dt)
  if self.hero and self:distance(self.hero) < self.reach then
    say("press E", 0.3)
  end
end

self is the object the script is on. Its built in fields and methods, such as self.position and self:tween, come from the engine; anything else you put on it, like self.open, is the script's own state.

Fields: variables you set in the editor

A global table named fields declares the variables the Inspector shows. Their values are saved with the scene and appear on self before start runs.

fields = {
  speed  = 5,                    -- number
  jumpy  = true,                 -- checkbox
  title  = "gate",               -- text
  power  = range(0.5, 0, 1),     -- slider from 0 to 1
  lives  = int(3),               -- whole number
  mode   = enum("idle", "patrol"), -- drop down, first is the default
  tint   = color("#ff8800"),
  offset = vec3(0, 0, 1),
  target = object(),             -- a GameObject slot
  lamp   = component("light"),    -- a component slot
  enemy  = prefab(),             -- a prefab slot, for spawn()
}

While the game runs the Inspector shows the live values, and editing one there changes it in the running script. Fields are listed in the order you wrote them.

Scripts talking to each other

Ask an object for a script by the script's file name and you get that script's self, functions included:

-- scripts/lever.lua
fields = { door = object() }

function key(self, k)
  if k == "e" then
    self.door:component("door"):toggle()  -- calls toggle(self) in door.lua
    return true
  end
end

Other components come back as handles whose fields are their Inspector properties: find("lamp"):component("light").radius = 12.

Hooks

HookWhen
start(self)Once, before the first update, and again after a reload.
update(self, dt)Every simulation step; dt is in seconds and follows time_scale.
key(self, k)On a key press. Return true to stop other components from also handling it.
on_destroy(self)Before the object is removed with destroy.
on_collision(self, other)When a collider of this object starts touching another, see Physics.
on_trigger(self, other)When a trigger collider starts overlapping another object.
draw(self, d)Every frame, to draw extra shapes; see the draw API.

The Lua API page lists every function, including the camera, the environment and the render pipeline, which scripts can change at run time.

Errors and hot reload

A runtime error stops only that script and appears in the Console with the file and line, for example scripts/door.lua:12: attempt to index a nil value. Double click it to jump to the line. Fix the file and save: the script reloads, keeps the state on self and runs start again.

Scripts and play modeScripts run in play mode and in built games. In the editor's Live preview they do not run, so editing never moves things by logic. Scripts run in a sandbox with the standard math, string and table libraries and no file, network or OS access.
