Lua scripting

Game logic is written in Lua files inside the project, in any code editor; the engine reloads a script when it is saved. Scripts are components: an object can carry several, and scripts can find and call each other.

Creating a script

  1. Select an object, press Add Component and choose New script with the name door. The editor creates door.lua in the folder open in the Project window, attaches it and opens it in the code editor.
  2. Replace the file's contents with the code below and save it.
  3. The script's card in the Inspector shows the fields hero, reach and lift. Drag the hero from the Hierarchy onto hero.
  4. Start play mode, walk to the door and press E.
-- door.lua
fields = {
  hero  = object(),
  reach = range(3, 1, 10),
  lift  = 4,
}

function start(self)
  self.open = false
end

function key(self, k)
  if k == "e" and self.hero and self:distance(self.hero) < self.reach then
    self.open = not self.open
    self:tween("pos.z", self.open and self.lift or 0, 0.6)
    return true
  end
end

function update(self, dt)
  if self.hero and self:distance(self.hero) < self.reach then
    say("press E", 0.3)
  end
end

self is the object the script belongs to. Its built in fields and methods, such as self.position and self:tween, are provided by the engine; any other value stored on it, such as self.open, is the script's own state.

Fields

A global table named fields declares variables that the Inspector shows and edits. Their values are saved with the scene and are set on self before start runs.

fields = {
  speed  = 5,                    -- number
  jumpy  = true,                 -- checkbox
  title  = "gate",               -- text
  power  = range(0.5, 0, 1),     -- slider from 0 to 1
  lives  = int(3),               -- whole number
  mode   = enum("idle", "patrol"), -- drop down, first is the default
  tint   = color("#ff8800"),
  offset = vec3(0, 0, 1),
  target = object(),             -- a GameObject slot
  lamp   = component("light"),    -- a component slot
  enemy  = prefab(),             -- a prefab slot, for spawn()
}

While the game runs, the Inspector shows the current values, and editing a value changes it in the running script. Fields are listed in the order of their declaration.

Calling other scripts

Asking an object for a component by a script's file name returns that script's self, including its functions:

-- lever.lua
fields = { door = object() }

function key(self, k)
  if k == "e" then
    self.door:component("door"):toggle()  -- calls toggle(self) in door.lua
    return true
  end
end

Other components are returned as handles whose fields are their properties: find("lamp"):component("light").radius = 12.

Hooks

HookWhen
start(self)Once, before the first update, and again after a reload.
update(self, dt)Every simulation step; dt is in seconds and follows time_scale.
key(self, k)On a key press. Returning true stops other components from handling the key.
on_destroy(self)Before the object is removed with destroy.
on_collision(self, other)When a collider of this object starts touching another, see Physics.
on_trigger(self, other)When a trigger collider starts overlapping another object.
draw(self, d)Every frame, to draw additional shapes; see Drawing from Lua.

The Lua API lists every function and field, including the camera, the environment and the render pipeline.

Errors and hot reload

A run time error stops only the script that raised it and appears in the Console with the file and line, for example door.lua:12: attempt to index a nil value. A double click on the message opens the file at that line. Saving the corrected file reloads the script; it keeps its state on self and runs start again.

Where scripts runScripts run in play mode and in built games, not in the editor's Live preview. They run in a sandbox with the standard math, string and table libraries and have no file, network or operating system access.
