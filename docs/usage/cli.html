CLI reference

ascdii starts the editor and provides the command line tools. Games run on ascdii-player.

Starting the editor

ascdii without arguments opens the editor at its start screen, so a double click on ascdii.exe starts it like any desktop program, see Install; ascdii run <project> opens it with a project, given as its folder or its manifest. The editor is always started through ascdii; started directly, it is restarted through ascdii run. With arguments, ascdii is the command line tool; ascdii help prints the list of commands.

Commands

CommandFunction
ascdii new <dir> [-name N] [-template dragonfall]Creates a project. Without a template, the project contains a manifest and a start scene with a camera.
ascdiiOpens the editor at its start screen.
ascdii run [project]Opens the editor, with the project when one is given.
ascdii play <dir> [--blocks]Plays a project folder in the terminal; --blocks draws half blocks instead of Braille, see Output modes. With mods enabled, the mods in the project's mods/ folder load and write their messages to mods/log.txt.
ascdii preview <dir> [-size 160x50] [-time 2] [-hour 22] [-plain] [-blocks]Prints one frame after simulating -time seconds, at an optional time of day; -plain omits colors, -blocks uses half blocks. Mod messages go to standard error.
ascdii build <dir> [-out path] [-player path] [-single]Builds a game folder with the player, data/game.pak and SHA256SUMS; -single builds one executable. The player defaults to the ascdii-player next to ascdii. See Build.
ascdii pack list <dir>Lists installed packages and the built in packages that are not installed.
ascdii pack install <dir> <file | name>Installs a .ascdiipack file or a built in package such as dragonfall.
ascdii pack remove <dir> <name>Removes a package and the modules only it required.
ascdii pack export <folder> -name N [-version V] [-description D] [-out file]Writes a folder, with its .meta files, as a .ascdiipack. See Packages.
ascdii versionPrints the engine version.
ascdii helpPrints the list of commands.

A built game accepts --blocks, and --preview [-size 160x50] [-time 2] to print one frame instead of starting. The environment variable ASCDII_BLOCKS=1 selects block mode for every game.

ascdii-player

ascdii-player runs games. A build is a copy of it, renamed to the game, with the game data appended or in data/ beside it; started this way it plays the game without arguments. Started on its own, it plays a project folder: ascdii-player <dir> [--blocks], or prints one frame with ascdii-player <dir> --preview and the options of ascdii preview.

Make targets

For working on the engine from source; see Building from source.

TargetFunction
make testgo vet and go test -race for the whole module.
make allBuilds bin/linux and bin/windows. Each folder is a complete installation for its platform and runs from any location it is copied to.
make cliBuilds ascdii and ascdii-player into bin/linux and bin/windows.
make editor-linux, make editor-windowsBuilds the editor into bin/linux or bin/windows, next to ascdii.
make editor-devRuns the editor with hot reload; it does not need to be started by ascdii.
make distBuilds the release archives in bin/dist.
make hello, make dragonfallRuns the two examples in the terminal.
make templateRegenerates the Dragonfall template from its Go source.
make brandDraws the icons of ascdii, the editor and the player, and writes the Windows resources that embed them. Every build target runs it first.
make benchMeasures the frame time of the sample scene.

The documentation has two maintenance tools: python3 docs/nav.py rewrites the navigation of every page, and go run ./cmd/docref docs/usage/components.html regenerates the component reference (with docs/usage/dragonfall.html dragonfall for the module).
