GameObjects and components

Everything in a scene is a GameObject: a name, a transform and a list of components. Components do the work: one draws a box, another is a light, another runs a Lua script. An object can have as many as it needs, including several of the same kind.

Creating objects

Open GameObject in the toolbar. When an object is selected, the new one is created as its child; otherwise it goes to the scene root at the center of the view.

EntryCreates
Create EmptyAn object with only a transform, for grouping and for scripts.
3D ObjectCube, Sphere, Cylinder, Cone, Plane, Quad, Ground, Water.
LightPoint, spot and directional lights.

Code modules add their own entries; installing the Dragonfall package adds a Dragonfall submenu with its terrain, castle, dragon and knight. Submenus open when you click them or rest the pointer on them, and moving diagonally across other rows does not switch them. The arrow keys, Enter and Esc work too.

Parents and children

Any object can hold other objects. Drag a row in the Hierarchy onto another row to make it a child, or onto Scene to move it back to the top. A child moves, turns and scales with its parent, which is how a lantern carries its flame and light, or a hand carries a sword. Reparenting keeps the object where it is on screen: its local values change so its place in the world does not. Scripts do the same with obj.parent = other or obj:set_parent(other), see the Lua API.

Moving, rotating and scaling

The Scene view's toolbar has three tools, also on W, E and R:

ToolDrag
MoveAn arrow along its axis, or the square in the middle along the ground.
RotateThe ring to turn around the up axis, or the red and green handles to tilt around X and Y.
ScaleA handle to stretch one axis, or the middle to scale evenly. Right or up grows, left or down shrinks.

Every drag is one undo step. Exact values go in the Transform card.

The Inspector

  • The header holds the name, the visibility checkbox, the tag (for find_by_tag in Lua) and Solid, which makes players collide with the object.
  • Transform comes first: position, rotation in degrees around X, Y and Z (Z is up), scale per axis, and flip, which mirrors sprites the 2.5D way of facing left. The values are local: relative to the parent object, or to the world for objects at the top.
  • Every component is a card with a checkbox to switch it off without losing its settings. The ⋮ button (or right click on the card) has Reset, Move Up, Move Down and Remove Component.
  • Add Component searches every kind and every Lua script in the project, grouped by category. Type to filter, use the arrow keys and Enter, or create a new script from the search text.

Prefab instances do not take new components; change the prefab instead, or unpack the instance.

Property names

A component's properties are named after its kind: light.radius, box.size. A second light on the same object is light#2, so its radius is light#2.radius. Animation keys, prefab overrides and Lua all use these names, and a short name such as radius also works when only one component has it.

References

Some properties point at something else instead of holding a value: another object, a component, a prefab, a texture or a material. They show as slots.

  • Object slots take a row dragged from the Hierarchy.
  • Component slots take a component card dragged from the Inspector header, or an object, in which case its first component of the wanted kind is used.
  • Prefab, texture and material slots take a tile dragged from the Project window.
  • The target button lists everything that fits, and None clears the slot.
  • A slot whose target was deleted shows Missing in red.

The toggle component's target and every object() or component() field of a Lua script are references.

How references are stored

Assets are named by the GUID in their .meta file. Objects inside a scene or prefab are named by a file id ("fid" in the file), unique within that file:

ValuePoints at
"5104…"An object of the same scene.
"5104…/3"Object 3 inside the prefab instanced as object 5104….
"~3"Object 3 of the prefab the reference itself belongs to.
"…#light"A component of that object, by its key.

New objects get random 53 bit file ids, so two people who add objects on different git branches can merge without clashing ids. References survive renaming and moving objects, saving and loading, duplicating (references inside the copy point at the copies), saving as a prefab and unpacking an instance.
