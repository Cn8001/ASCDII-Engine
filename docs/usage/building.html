Build and release

A build is the ascdii player with your project packed onto its end. One file per platform, nothing to install.

From the editor

  1. Press Build in the toolbar or Ctrl+B.
  2. Choose the platforms. Both are on by default.
  3. Check the version and press Build. Unsaved changes are saved first, so the build always matches the editor.
  4. Press Show to open the output folder.

The result in build/release/<name>-<version>/:

Dragonfall-0.1.0-linux-amd64
Dragonfall-0.1.0-linux-amd64.zip
Dragonfall-0.1.0-windows-amd64.exe
Dragonfall-0.1.0-windows-amd64.exe.zip
SHA256SUMS

The version you enter is stored in the manifest, so the next build starts from it.

From the command line

# one executable for this machine
ascdii build ~/games/quest

# a release for every player found in bin/players
ascdii release ~/games/quest -version 0.2.0 -players bin/players

Publish on GitHub

git tag v0.2.0
git push --tags
gh release create v0.2.0 build/release/Quest-0.2.0/* --title "Quest 0.2.0"

Players download the file for their platform and run it in a terminal. The checksums let them verify the download.

Running a built game

./Quest-0.2.0-linux-amd64
Quest-0.2.0-windows-amd64.exe

# a still frame without a terminal, for screenshots or CI
./Quest-0.2.0-linux-amd64 --preview -size 160x50 -time 2
VersionsThe engine is 0.0.1. Empty projects start at 0.0.1, projects from the Dragonfall template at 0.1.0. The manifest also records the engine version the project was last saved with.
