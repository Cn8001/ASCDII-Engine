Assets and import

The Project window is the project folder on disk. Organize it in folders, drop files into it from your file manager, and share assets between projects without breaking a single reference.

Folders

  • Click a folder in the tree, or double click a folder tile, to open it. The path above the tiles takes you back up.
  • Create, or right click empty space, makes a folder, a script, a scene or a material in the open folder.
  • Drag tiles or folders onto a folder in the tree, a folder tile or the path to move them. The .meta files move along, so references keep working.
  • Right click a folder to rename or delete it, and a tile to rename or delete it. Deleting asks first and removes the files from disk; anything that used them shows Missing.
  • Search and the type filter look through every folder; right click a result and choose Show in Folder.

.meta files and GUIDs

Every asset has a .meta next to it with a UUIDv7 that never changes, and everything refers to assets by that id. Some kinds keep their import settings in it too:

{
  "format": 1,
  "guid": "019a0f3e-7c41-7b2a-9d55-3f1c8e2a9b40",
  "import": { "maxSize": 128, "filter": "nearest", "alphaCutoff": 0.5 }
}

Commit .meta files together with their assets. A teammate who clones the project gets the same ids, so their scenes and yours agree.

Sharing between projects

To move a set of assets to another project, for example a prefab with its scripts, models and art, copy their folder with the .meta files and drop it on the other project's Project window. Imported assets keep their GUIDs, so the prefab still finds its scripts and textures. If the other project already has an asset with the same GUID, the copy gets a new one, which keeps both apart; files that are not assets, such as notes, are copied as they are.

Changes made outside the editorFiles you change in another program are picked up while the editor runs: scripts reload, art, models, textures and materials refresh. The reload button in the Project window rescans everything.
