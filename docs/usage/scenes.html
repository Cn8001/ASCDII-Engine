Scenes and prefabs

How a world is put together: projects, scenes, prefabs and overrides, and the single unit everything is measured in. Objects and their components have their own page, GameObjects and components.

The project folder

MyGame/
  MyGame.ascdiiproj       manifest
  scenes/*.scene.json     object trees, camera, environment, clips
  prefabs/*.prefab.json   reusable object trees
  models/*.obj            models, with their .mtl files
  textures/*.png          pictures for materials
  materials/*.material.json
  art/*.json, *.xp        glyph art: palette JSON or REXPaint
  scripts/*.lua           scripts in Lua
  packages/<name>/       installed packages, read only
  **/*.meta               one per asset: its permanent id
  build/                  output, ignored by git

Asset ids and .meta files

Every asset has a .meta file next to it holding a UUIDv7, like Unity's GUIDs:

{
  "format": 1,
  "guid": "019a0f3e-7c41-7b2a-9d55-3f1c8e2a9b40"
}

Scenes refer to prefabs, scripts, models, materials and art by this id, never by path. Rename or move an asset in the Project window (right click, Rename) and the .meta goes with it, so nothing that uses it breaks. Commit the .meta files together with their assets; when you move files with git or a file manager, move the .meta too.

Older projectsOpening a project without .meta files creates them and rewrites path references in the scene to ids. The Console reports how many changed; save to keep the result.

The manifest is short and readable:

{
  "format": 1,
  "name": "Dragonfall",
  "version": "0.1.0",
  "engine": "0.0.1",
  "start": "scenes/dragonfall.scene.json",
  "cols": 160, "rows": 50, "fps": 30,
  "modules": ["dragonfall"]
}

modules lists the Go code modules the project uses; the sample uses the Dragonfall module for its terrain, castle, dragon and knight. Installing a package adds the modules it needs, and projects that only use built in components have none. Files from before 0.0.1 call this list packs; it is read the same way.

World units

Everything is measured in world units, where one unit is one tile of ground. A knight is about 4 units tall, a castle wall 8, a tower with its roof about 20. You never type dots, cells or depth values: the camera projects positions, and depth comes from the projection. That is also why objects never sink into each other by accident.

Collision uses the same shape you seeMark an object Solid and players cannot walk through it. The blocking area is the object's own bounds, so what you see is what you bump into. Complex components such as the castle block with their walls and towers, not their bounding box.

Prefabs

  1. Build something once, for example a lantern: a post, a flame emitter and a light as children.
  2. Right click its root in the Hierarchy and choose Save prefab, then give it a name. The object becomes an instance of prefabs/<name>.prefab.json.
  3. Place more of them by dragging the prefab from the Project window into the view or onto the Hierarchy.
  4. Edit the prefab file (or save a changed copy over it) and every instance updates.
  5. Need a one off variation? Right click an instance and Unpack it into ordinary objects.

An instance stores its own name, transform and visibility, the prefab id, and a list of overrides; everything else comes from the prefab. That keeps scene files small and diffs readable.

Overrides

Select an instance, or anything inside it, and change a value. Instead of being locked, the change is recorded as an override on the instance: the label turns bold amber, the Hierarchy shows an amber dot and a band at the top of the Inspector counts the overrides.

  • Right click an overridden label for Apply to prefab (write the value into the prefab, so every instance gets it) or Revert (go back to the prefab's value).
  • Apply and Revert in the band do the same for every override of the instance.
  • Overrides survive the prefab changing. If the prefab no longer has the child an override points at, the override is kept but does nothing.
{
  "name": "lantern 1",
  "pos": [100, 76.3, 0],
  "prefab": "01a160e8-5000-7dc8-8295-00ff6a1eb491",
  "overrides": [
    { "path": "glow", "prop": "light.radius", "value": 18 },
    { "path": "glow", "prop": "light.color", "value": "#ff8844" }
  ]
}

Scenes

A project can have many scenes. Use the scene picker in the toolbar or double click a scene in the Project window to open one, and the key button to make the open scene the one a build starts with. New scenes start empty; the Scene view shows a ground grid until you add something.
