Scenes and prefabs

The structure of a project: its folder, the manifest, asset ids, scenes, prefabs and overrides, and the unit all sizes are given in. Objects and components are described in GameObjects and components.

The project folder

Only the manifest has a fixed place, at the top of the project folder. All other files may be organized in any folder layout, for example:

MyGame/
  MyGame.ascdiiproj       manifest: name, version, start scene
  scenes/main.scene.json  object trees, camera, environment, clips
  knight/                 for example, one folder per character:
    knight.prefab.json      a reusable object tree
    knight.lua              its script
    knight.sprite.json      glyph art: palette JSON, or .xp from REXPaint
    swing.wav               a sound
  props/barrel.obj        models, with their .mtl files and textures
  props/wood.material.json
  packages/<name>/       installed packages, read only
  **/*.meta               one per asset: its permanent id
  build/                  output, ignored by git

The manifest

The .ascdiiproj file describes the project:

{
  "format": 1,
  "name": "Dragonfall",
  "version": "0.1.0",
  "engine": "0.0.1",
  "start": "scenes/dragonfall.scene.json",
  "cols": 160, "rows": 50, "fps": 30,
  "modules": ["dragonfall"]
}
FieldMeaning
formatVersion of the manifest format.
name, versionThe game's name and version; builds are named after them.
engineThe engine version the project was last saved with.
startThe scene a game starts with.
cols, rowsThe terminal size the game is designed for, in cells.
fpsFrames per second of the game loop.
modulesThe Go code modules the project uses, such as dragonfall for the sample's terrain, castle, dragon and knight. Installing a package adds the modules it requires. Older files name this list packs; it is read the same way.

Asset ids and .meta files

Every asset has a .meta file next to it that holds a permanent id, a UUIDv7, and the asset's import settings:

{
  "format": 1,
  "guid": "019a0f3e-7c41-7b2a-9d55-3f1c8e2a9b40"
}

Scenes and prefabs refer to assets by this id, never by path. Renaming or moving an asset in the Project window moves its .meta file along, so every reference remains valid. Files moved outside the editor must be moved together with their .meta files, and both belong under version control.

Older projectsOpening a project without .meta files creates them and rewrites path references to ids; the Console reports the number of changes, and saving keeps the result. Sprites stored as plain .json files are renamed to .sprite.json, together with their .meta files.

World units

All positions and sizes are given in world units; one unit is one tile of ground. The Dragonfall knight is about 4 units tall, a castle wall 8, a tower with its roof about 20. The camera projects world positions onto the terminal; depth follows from the projection, so objects are sorted correctly without depth values in the scene.

CollisionAn object marked Solid blocks the player with its bounds; complex components such as the castle block with their walls and towers. Colliders define collision shapes explicitly, see Physics.

Scenes

A project can contain any number of scenes. The scene picker in the toolbar and a double click on a scene in the Project window open a scene; the key button next to the picker makes the open scene the start scene. Create, Scene in the Project window creates a scene in the open folder, containing a Main Camera. A scene file stores the object tree, the environment and the animation clips; the camera is an object in the tree.

Prefabs

  1. Build an object once, for example a lantern from a post with a flame emitter and a light as children.
  2. In the Hierarchy, open the context menu of its root, choose Save prefab and enter a name. The prefab is saved in the folder open in the Project window, or at the given path, and the object becomes an instance of it.
  3. Further instances are placed by dragging the prefab from the Project window into the Scene view or onto the Hierarchy.
  4. Changes to the prefab update every instance.
  5. Unpack in an instance's context menu turns it into ordinary objects.

An instance stores its own name, transform and visibility, the prefab's id and a list of overrides; everything else is read from the prefab.

Prefab mode

A double click on a prefab in the Project window opens it on its own. The toolbar shows the prefab's name with Save and Back. Save writes the prefab file; Back returns to the scene with its undo history and unsaved changes intact, and every instance shows the saved prefab. A prefab has exactly one root object. Prefabs of installed packages open read only.

Overrides

Changing a value on an instance, or on an object inside it, records an override on the instance. The property label turns bold amber, the Hierarchy marks the instance with an amber dot, and a band at the top of the Inspector shows the number of overrides.

  • The context menu of an overridden label provides Apply to prefab, which writes the value into the prefab for every instance, and Revert, which restores the prefab's value.
  • Apply and Revert in the band act on all overrides of the instance.
  • Overrides are kept when the prefab changes. An override whose target no longer exists in the prefab has no effect.
{
  "name": "lantern 1",
  "pos": [100, 76.3, 0],
  "prefab": "01a160e8-5000-7dc8-8295-00ff6a1eb491",
  "overrides": [
    { "path": "glow", "prop": "light.radius", "value": 18 },
    { "path": "glow", "prop": "light.color", "value": "#ff8844" }
  ]
}
