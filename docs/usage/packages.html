Packages

A package is a set of assets, with their .meta files, that you add to a project and take out again as a whole, like a Unity package. It is built like a project but does not run on its own: it brings prefabs, models, textures, materials, scripts and scenes for your game to use.

The Package Manager

Open it with the package button in the toolbar. On the left are the packages In Project and those Available to install; on the right are the details of the one you pick.

  • Install copies the package into packages/<name>/ and loads it. Its prefabs, models and scripts are ready to use at once.
  • Update appears when a newer version is available and replaces the installed one.
  • Remove takes the package out of the project. Anything in your scenes that used its assets shows as missing.
  • Install from file installs a .ascdiipack from anywhere on disk.

Available packages come from two places: those built into the editor, such as the Dragonfall sample, and every .ascdiipack in your package folder (~/.config/ascdii/packages on Linux, %AppData%\ascdii\packages on Windows). Put the packages you use often there.

Installed packages are read only

Packages appear under Packages in the Project window. Use their assets as you would your own: drag a prefab into the scene, put a material on an object, open a sample scene and press play. You cannot rename, move, delete or change files inside a package, and scenes inside a package cannot be saved, so updating or removing it never loses your work. To change a package asset, copy what you need into your own folders first.

Code modules

Some packages use components written in Go, which have to be built into the editor and the player. Dragonfall's terrain, castle, dragon and knight are such a module. A package names the modules it needs; installing it adds them to the project manifest, and their components appear in the GameObject menu and Add Component. Removing the package removes its modules again, unless your own scenes or another package still use them. A package that needs a module this editor was built without shows a warning and cannot be installed.

A new, empty project has no modules, so it shows only the engine's own components.

Making a package

  1. Put the assets in one folder of your project, for example props/street, with everything they need.
  2. Right click the folder in the Project window and choose Export Package. Right click Assets to export the whole project.
  3. Give it a name (lower case letters, digits, dots and dashes) and a version, then pick where to save the .ascdiipack.

The file is a zip with the assets, their .meta files and a pack.json:

{
  "format": 1,
  "name": "street-props",
  "version": "1.0.0",
  "engine": "0.0.1",
  "description": "Lanterns, benches and signs",
  "modules": []
}

Assets keep their GUIDs, so references between them survive the trip. If a project already has an asset with one of the package's GUIDs outside the package, installing stops and names the clashing files, since one id cannot name two assets.

From the command line

ascdii pack list MyGame
ascdii pack install MyGame dragonfall
ascdii pack install MyGame ~/Downloads/street-props-1.0.0.ascdiipack
ascdii pack remove MyGame street-props
ascdii pack export MyGame/props/street -name street-props -version 1.0.0
